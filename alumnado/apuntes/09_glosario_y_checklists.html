1. Glosario rápido del proyecto

TérminoSignificado práctico
BackendParte del sistema que recibe peticiones, aplica lógica y accede a la base de datos.
APIInterfaz que permite que otros sistemas se comuniquen con el backend.
EndpointRuta concreta de la API, asociada normalmente a un método HTTP.
RequestPetición que llega al servidor.
ResponseRespuesta que devuelve el servidor.
PayloadContenido del evento o del body enviado.
ORMHerramienta para trabajar con base de datos desde código.
PrismaORM utilizado en el proyecto.
ValidatorBloque que comprueba si la entrada tiene la forma correcta.
ServiceCapa donde se aplica la lógica de negocio.
RepositoryCapa que consulta o modifica la base de datos.
SeedCarga de datos iniciales para pruebas.

2. Checklist de análisis y diseño

  • entiendo qué problema resuelve VigiaSenior;
  • sé cuál es la regla principal del sistema;
  • puedo nombrar las entidades principales del dominio;
  • sé qué endpoints mínimos tiene el proyecto;
  • puedo explicar qué espera cada endpoint;
  • tengo claro qué entra en el MVP y qué quedaría como ampliación.

3. Checklist técnico de entorno

  • he clonado el repo correctamente;
  • he instalado dependencias;
  • he generado Prisma Client;
  • he aplicado migraciones;
  • he cargado seed si el proyecto lo requiere;
  • el endpoint /health responde;
  • puedo lanzar tests con npm test.

4. Checklist de implementación de una funcionalidad

  • he definido qué debe hacer la ruta;
  • he creado o revisado el validador necesario;
  • el controlador delega en el servicio y no hace demasiadas cosas;
  • el servicio contiene la lógica de negocio relevante;
  • las consultas a base de datos están encapsuladas en repositorio;
  • la respuesta JSON tiene forma clara y consistente;
  • he probado el caso feliz y al menos uno de error.

5. Checklist de pruebas

  • he probado con Postman la ruta principal;
  • he probado un body válido y uno inválido;
  • he revisado el código de estado HTTP;
  • he comprobado si la base de datos refleja el cambio;
  • si la funcionalidad es crítica, he añadido o revisado test automático.

6. Qué significa realmente avanzar en el proyecto

No siempre avanzar significa escribir muchas líneas. A veces un buen avance es:

  • entender mejor una regla de negocio;
  • simplificar una respuesta JSON;
  • detectar una incoherencia entre endpoint y modelo;
  • añadir una prueba que evita un error futuro;
  • dejar una ruta más clara y más fácil de mantener.

Un backend bien hecho no se mide solo en cantidad de código, sino en claridad y comportamiento correcto.

Estos apuntes están pensados como soporte real de trabajo. La idea es que el alumnado pueda usarlos mientras diseña, implementa, prueba y documenta el backend.
