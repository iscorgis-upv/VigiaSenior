Objetivos generales y competencias vinculadas

Encaje curricular de VigiaSenior dentro del módulo 0613 · Desarrollo web en entorno servidor. Este documento resume qué objetivos, competencias y bloques del módulo se trabajan con el proyecto.

Contexto académico

VigiaSenior se plantea como una programación de aula basada en proyecto para el ciclo de Desarrollo de Aplicaciones Web. El trabajo se sitúa en el módulo de Desarrollo web en entorno servidor y se organiza como un bloque específico de diez sesiones.

Ubicación dentro del módulo

El módulo puede organizarse en tres grandes bloques. VigiaSenior se apoya sobre todo en la parte de programación en entorno servidor y en el bloque de servicios web y aplicaciones web híbridas.

Bloque 2 · Programación en entorno servidor

En este bloque se sitúan la generación dinámica de páginas y el acceso a datos. En el proyecto se trabaja especialmente a través de la separación de capas, la persistencia y la lógica de negocio.

  • RA5 · Separación entre presentación y lógica de negocio.
  • RA6 · Acceso a almacenes de datos y mantenimiento de la información.

Bloque 3 · Servicios web y aplicaciones híbridas

Es el bloque más visible del proyecto, ya que el backend se comunica con un dispositivo o simulador mediante una API REST y registra eventos para alimentar el seguimiento de la medicación.

  • RA7 · Desarrollo, descripción, verificación y consumo de servicios web.
  • RA8 · Páginas o interfaces dinámicas de consulta y visualización.
  • RA9 · Integración de librerías, reutilización de código y documentación final.

Mapa conceptual del proyecto

El proyecto se entiende mejor como la unión de tres partes: una parte física o simulada, una capa de comunicación y un backend que concentra la lógica de negocio.

Parte física

  • Pastillero inteligente.
  • Arduino Nano ESP32.
  • Sensores de apertura.
  • LEDs, buzzer y botón de confirmación.

Comunicación

  • Wi‑Fi y API REST.
  • Consulta del plan del día.
  • Envío de eventos del dispositivo.
  • Simulación cuando no se use hardware físico.

Backend

  • Configuración de paciente y cuidador.
  • Planificación semanal configurable.
  • Estados de toma y alertas.
  • Base de datos, API y dashboard de consulta.
El hardware valida una parte del sistema, pero el caso completo se modela en el backend: planificación, eventos, persistencia, estados, alertas y consulta posterior.

Enfoque metodológico asociado

La metodología principal es el Aprendizaje Basado en Proyectos. El alumnado trabaja sobre un reto concreto, avanza por fases y entrega evidencias parciales que permiten revisar el proceso antes de llegar al producto final.

La propuesta también tiene una orientación próxima al Aprendizaje-Servicio, porque parte de una necesidad social reconocible: apoyar el seguimiento de la medicación en personas mayores. Aun así, no se plantea como un ApS completo, ya que se parte de una necesidad previamente identificada en el contexto de una residencia de mayores.

La organización prevista es de equipos de tres personas, con reparto de tareas técnicas y documentales. Esta estructura permite trabajar el backend, la base de datos, las pruebas, la documentación y la defensa de forma coordinada.
